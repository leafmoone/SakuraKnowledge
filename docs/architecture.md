# Architecture / implemented boundary

`model.py`: frozen keys, evidence statuses, fixed image groups and version-1 NFKC/casefold tokenization (Latin words, overlapping CJK bigrams). `storage.py`: SHA-locked normalized JSONL importer, 1000-row commits, SQLite foreign keys, per-record savepoints, safe publication. `api.py`: shared offline read-only query layer. `cli.py`: JSON command boundary and opt-in latest metadata fetch. `safety.py`: digest-checked ZIP extraction into a new directory. `mapping.py`: candidate cardinality/missing/reverse-consistency audit only.

SQLite tables: sources, entries, aliases, documents, occurrences, links, build_meta, search_fts. Each alias/document/link has independent evidence. Raw alias/document/link/occurrence JSON survives in payload. New revisions should receive distinct source_id values. Snapshot identity currently hashes the manifest. Query connections use mode=ro, immutable=1 and query_only; only closed, published snapshots may be read. Builders use rollback journals; checkpoint is still requested before publication. A sibling temporary directory is renamed only after integrity, foreign-key and input digest checks.

Known engineering gaps: duplicate detection keeps an in-memory set per source; link rows must follow both endpoints; rejected/unresolved inputs block publication rather than publishing a partial snapshot; rejection reports are currently exception text, not durable artifacts. Counts are per source, not yet per entity type. Conflict quarantine, cross-version entry metadata history, full canonical citation assembly, large-document token boundary semantics, independent file inventory validation and full FTS consistency verification need hardening. This is a baseline, not the complete production architecture.
