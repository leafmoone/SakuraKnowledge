# Contract v2 (normalized engine; real adapters blocked)

Manifest: JSON object with sources array and optional index_episodes=false. TOML parses too, but JSON is recommended because unknown metadata must remain null, not an invented value. Required fields are defined in `storage.REQUIRED_SOURCE`: source_id, provider, dataset_role, repo (no credentials), upstream_revision, asset_name, upstream_digest, local_sha256, source_declared_cutoff, exported_at, fetched_at_utc, inspected_at_utc, schema_version, importer_version, mapping_generator_revision, input_file_inventory, counts, source_references, refresh_status, code_license, data_license, path, adapter. Only adapter=contract-jsonl-v1 is accepted. Paths resolve relative to manifest; digests are SHA256 hex. Metadata presence and essential source-id/repo/path/digest types are checked; inventory and source-declared-count typing remain incomplete. Each physical JSONL record is capped at 2 MB, and source bytes are copied into a private temporary file while their SHA is checked; import reads that copy, never a reopened mutable source.

JSONL entity: key={kind,namespace,value}, optional type/locator/status/evidence_id, aliases=[{text,language,type,status,evidence_id}], documents=[{title,original,language,status,evidence_id}], occurrences=[{dataset,group,frequency}]. Evidence IDs default to source-id:file-sha:line:N. Additional entity/alias/document/occurrence fields remain in their versioned payload. Direct key/value hits require trusted entry evidence and no type/locator conflict; draft-only documents or aliases cannot make a tag a reliable identity. Even one-directional or bidirectional mapping candidates do not qualify as verified.

JSONL link: record_type=link, src/dst full keys, relation, method, verification_status in native/redirect/candidate/verified/conflict. Original link payload and source line locator survive. Statuses on alias/doc: source_backed/generated_from_evidence/unverified_draft/no_reference/conflict/failed. Only the first two are queried by default. A source-backed identity with no descriptive document may still have entry evidence; otherwise an entity whose only attached evidence is draft is draft by default. Candidates are never promoted by the importer. A trusted upstream normalization producer is required; asserted verified input is not itself human fact review.

Output result: contract_version, snapshot, query, status, entry_key, tag_key, canonical, candidates, descriptions, relations, citations, warnings. Descriptions contain source_id/evidence_id, original text limited to 4000 characters. Search candidate descriptions retain citations locally. Alias-only exact hits carry matching alias evidence in top-level citations, not unrelated document citations. Limits: query 4096 characters and 256 tokens; indexed document 100000 characters and no query-token truncation; topk/related max 100; SQLite query progress deadline 5 seconds; ranked FTS document scan 10001 maximum (warning if incomplete). Episode keys import while episode FTS defaults off. Revisioned entry metadata records keep independent dates; a later body record does not refresh old mapping metadata.
