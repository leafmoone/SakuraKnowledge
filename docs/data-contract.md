# Contract v2 (local audited engine; evidence boundaries explicit)

Manifest: JSON object with sources array and optional index_episodes=false. TOML parses too, but JSON is recommended because unknown metadata must remain null, not an invented value. Required fields are defined in `storage.REQUIRED_SOURCE`: source_id, provider, dataset_role, repo (no credentials), upstream_revision, asset_name, upstream_digest, local_sha256, source_declared_cutoff, exported_at, fetched_at_utc, inspected_at_utc, schema_version, importer_version, mapping_generator_revision, input_file_inventory, counts, source_references, refresh_status, code_license, data_license, path, adapter. Only adapter=contract-jsonl-v1 is accepted. Paths resolve relative to manifest; digests are SHA256 hex. Metadata presence and essential source-id/repo/path/digest types are checked; inventory and source-declared-count typing remain incomplete. Each physical JSONL record is capped at 2 MB, and source bytes are copied into a private temporary file while their SHA is checked; import reads that copy, never a reopened mutable source.

## Local source boundary

The fixed Bangumi Archive, Moegirl, Danbooru Wiki, and tag-wiki inputs are `LOCAL_AUDITED_AND_BUILT` for the recorded local cuts. This is not a live upstream refresh and not full human source-fact review. The audited cut contains no native `danbooru.tag` identities and zero verified `entity_tag` links. Candidate mappings, shared spellings, wiki titles, and confidence values cannot establish a cross-namespace identity.

JSONL entity: key={kind,namespace,value}, optional type/locator/status/evidence_id, aliases=[{text,language,type,status,evidence_id}], documents=[{title,original,language,status,evidence_id}], occurrences=[{dataset,group,frequency}]. Evidence IDs default to source-id:file-sha:line:N. Additional entity/alias/document/occurrence fields remain in their versioned payload. Direct key/value hits require trusted entry evidence and no type/locator conflict; draft-only documents or aliases cannot make a tag a reliable identity. Even one-directional or bidirectional mapping candidates do not qualify as verified.

Moegirl raw fields such as `raw_attributes`, `raw_subject_categories`, `raw_cv_names`, and `raw_gender` are preserved as source payload. They are not automatically converted into Danbooru tags, `character_of` relations, or Bangumi person joins. `char2subject` categories remain raw categories, and CV names remain raw names.

JSONL link: record_type=link, src/dst full keys, relation, method, verification_status in native/redirect/candidate/verified/conflict. Original link payload and source line locator survive. Statuses on alias/doc: source_backed/generated_from_evidence/unverified_draft/no_reference/conflict/failed. Only the first two are queried by default. A source-backed identity with no descriptive document may still have entry evidence; otherwise an entity whose only attached evidence is draft is draft by default. Candidates are never promoted by the importer. A trusted upstream normalization producer is required; asserted verified input is not itself human fact review.

Trust split: `IDENTITY_TRUSTED` = {source_backed} gates every identity decision (exact-key lookup, value/alias resolution, search/related visibility, ask targets, entry default status). `TEXT_TRUSTED` = {source_backed, generated_from_evidence} gates descriptions and FTS only: a generated document may be described/searched under a source-backed identity, but a generated alias alone never resolves, a generated-only record never auto-becomes a source_backed identity, and candidate/unverified_draft/no_reference/conflict/failed material is never identity. Verified `entity_tag` edges still resolve only between trusted identities.

Output result: contract_version, snapshot, query, status, entry_key, tag_key, canonical, candidates, descriptions, relations, citations, warnings. `ask` additionally parses a bounded deterministic template set — "X 的 Danbooru tag 是什么" (case-insensitive `danbooru`), "X 的标签是什么", "介绍一下 X" — extracting X verbatim (inner punctuation/brackets/underscores untouched) with `query_template` = danbooru_tag/tag/introduce; the Danbooru template implies `target_tag_namespace=danbooru.tag` and an explicit conflicting target is rejected. Anything else keeps the direct-entity-name behaviour with `query_template=unsupported`, and an unsupported query that matches nothing returns `unknown` with the `unsupported_query_template` warning — never a guess. `ask` additionally includes `target_namespace` and `mapping_status`: source `--namespace` filters identities only, while `--target-tag-namespace` asks independently for a target tag. With no requested target, a source-local aggregate tag may be `found` with `mapping_status=local_identity_only`; this is NOT a Danbooru tag. A requested Danbooru target with only a local match retains the source `entry_key`/`canonical` but yields `tag_key=null`, `mapping_status=target_unmapped`. Verified `entity_tag` links or direct trusted identities in the actual target namespace alone can resolve that target; equal spellings, title evidence, unique and bidirectional candidate links cannot. Descriptions contain source_id/evidence_id, original text limited to 4000 characters, and explicit `response_truncated`/`search_text_truncated` flags; full original survives in the snapshot. Search candidate descriptions retain citations locally. Alias-only exact hits carry matching alias evidence in top-level citations, not unrelated document citations. Limits: query 4096 characters and 256 tokens; indexed document 100000 characters and no query-token truncation; topk/related max 100; SQLite query progress deadline 5 seconds; ranked FTS document scan 10001 maximum.
